## 2. 本人身份导入过程（核心）

### 2.1 飞书：账号页 →「连接本人账号」（假 App ID）

**未配置凭据时**（全 mock 场景）：账号页飞书/钉钉卡片显示「身份 · 谁在收、谁在发 / 接收：模拟 / 发送：模拟」，并明确写：
> 「当前平台通道是『Mock 模拟』：不会真实收发。要使用本人账号，请先在 .env 配置该平台凭据并重启后端，再回来连接。」

→ 好评：**Mock 阶段不会给出可点的"连接本人账号"按钮**，避免小白点进一个必然失败的 OAuth。

**配了假 App 凭据（真实通道）时**：卡片出现「连接本人账号」按钮，状态为「已配置（未验证）」+ 可复制的 `pnpm run doctor --platform=feishu`（P1-1 修复，见 §4）。

**点「连接本人账号」后（无头浏览器环境，弹窗被拦截）**：LinkHub 没有白屏/无反应，而是给出完整兜底面板（截图 `p2-05`）：
> 「浏览器拦截了飞书授权窗口 / 授权页没能自动打开。点下面的按钮或复制链接，在新标签里完成授权；完成后回到本页会自动刷新状态。」
> 按钮：`打开飞书授权页` / `复制授权链接` / `查看配置步骤（常见失败原因）` / `重新发起授权` / `我知道了`

**授权失败回跳后**：账号页顶部出现中文可操作提示（截图 `p2-09` 顶部）：
> 「授权未完成。最常见原因：飞书应用还没发布/未加入可用范围、重定向 URL 与飞书后台不一致、用户身份权限未开通（im:message、im:message:readonly 等）。飞书页面上的错误码（如 20028）多半指向这几项配置。」

→ **P1-6 已修复**：不再只把用户丢在飞书错误页，回跳后有原因解释和配置指引；弹窗被拦也有手动入口。
→ 未复现：真实账号成功授权后的回调（需真人）；真实重定向失败回调（只用假 App ID 观察了飞书侧 20028 与 LinkHub 回跳提示）。

### 2.2 钉钉：账号页 →「连接本人账号」弹窗（dws 已安装、未登录）

点钉钉卡片的「连接本人账号」→ 弹出「连接钉钉本人账号」弹窗（截图 `p2-07`），普通用户能看到：

1. **三句话解释**：不用把机器人拉进群；登录的是本机 dws 官方 CLI，LinkHub 只读「已登录/未登录」状态、不接触密码；随时可回退机器人兜底（或 `DINGTALK_IDENTITY=bot`）。
2. **当前状态**：「尚未登录钉钉本人身份：当前用机器人收发；推荐连接本人账号…」
3. **登录说明**：「点下面的『开始登录』，LinkHub 会调用本机 dws 拉起钉钉官方授权页。完成后这个弹窗会自动变成『已连接』… 也可以在终端自己执行：`dws auth login`」
4. **按钮**：`开始登录` / `我已登录，刷新状态` / `重新检测本机 dws` / `关闭`；底部「正在自动检测本机登录状态」。

**点「开始登录」后**（截图 `p2-08`）：
- 弹窗出现「请在浏览器 / 手机完成授权」；
- 「已启动钉钉设备码登录：请打开钉钉/浏览器访问下方授权地址，输入设备码并确认授权；完成后回到本页点『我已登录，刷新状态』（页面会自动刷新）。」
- 展示：授权链接（钉钉官方 `login.dingtalk.com/oauth2/device/verify.htm?...`，带复制按钮）、**设备码 `DRRX-QTFT`（带复制按钮）**、终端等价命令 `dws auth login --device`（带复制按钮）；
- 状态行：「正在自动检测登录状态（每 2 秒一次，最多等 2 分钟）…」，提供「重新发起登录」。

**普通用户会卡在哪（如实记录）**：
- 需要**手机钉钉扫码/确认**，纯电脑用户如果没装手机钉钉或不在手机旁，会卡在"授权链接打开后让我在钉钉里确认"；
- 设备码是 8 位、需要先打开链接再手动输入，小白可能不知道怎么把"设备码"和"链接"配合；
- 企业侧若不允许第三方 CLI 登录/未开企业应用访问权限，错误会显示在钉钉页面而不是 LinkHub（本次我未完成授权，**"管理员权限不足"的具体报错未复现**，属时间盒外）；
- 2 分钟自动轮询超时后的提示未实测（时间盒内未等到 2 分钟）。

## 5. 新发现问题（阶段二）

### NEW-P2-1 本人身份已连接时，卡片顶部摘要仍显示「不可接收/不可发送」，与身份块「接收=本人、发送=本人」矛盾

- **现象**：fake-dws 已连接状态下，钉钉卡片顶部摘要显示「**不可接收**」（机器人通道的收能力），但同一张卡的身份块写「接收 **本人** / 发送 **本人**」，且页面文案说「下面每张卡片的『接收 / 发送』就是当前生效身份」。
- **我以为**：连上本人后卡片应显示可接收/可发送，或至少摘要跟随生效身份。
- **实际**：摘要按"机器人兜底通道"算，身份按"生效身份"算，两个口径并列，小白会以为"连上了但还是收不到"。
- **证据**：`p2-09-accounts-dingtalk-user-connected.png`（文本：`钉钉 / 不可接收 / 身份 · 谁在收、谁在发 / 接收 本人`）。
- **建议**：摘要徽标改为「接收：本人 / 发送：本人」，机器人能力放到"兜底通道"里单独一行。

### NEW-P2-2 fake-dws 离线演示会把收件箱灌成重复消息

- **现象**：fake-dws 事件订阅每轮推送多条事件，几分钟内收件箱出现 **9 条**消息，其中同样内容重复 3 份（"周二前交周报"/"待办"等），都标「本人账号接收」。
- **我以为**：离线演示会收到固定的 1–2 条示例。
- **实际**：重复消息堆满列表（`received=6, deduped=2`），演示/评审时看起来像"重复收件"缺陷。
- **证据**：`p2-10-inbox-user-received.png`。
- **建议**：fake-dws 默认只推送一轮固定事件（或支持 `FAKE_DWS_EVENTS=once`），并在 `docs/personal-identity.md` 说明离线演示预期条数；前端对同 externalId 已有幂等，但 fake 桩的消息 ID 每次不同导致去重不了。

### NEW-P2-3 同步拦截的 toast 建议「改用 identity=user」，但该状态下本人身份不可用

- **现象**：`FEISHU_MODE=real` 但缺凭据时，toast 提示「…请补齐凭据后重试，**或改用 identity=user 以本人身份发送**」；但此时本人身份未连接（Compose 里只有「机器人发送」且不可切换）。
- **我以为**：可以按提示切成本人身份。
- **实际**：没有可选项，提示给了用户做不到的下一步。
- **证据**：`p2-17-send-toast.png`（toast 文本 + 弹窗「当前只能以机器人身份发送：本人账号未连接」）。
- **建议**：提示按实际能力分支：本人不可用时只提示"补齐凭据/先连接本人账号"，不出现"改用 identity=user"。

### NEW-P3-1 钉钉设备码弹窗直接展示带长参数（callerUmt）的授权链接

- **现象**：授权链接以长 URL 纯文本展示（有复制按钮），含 `callerUmt` 等参数；设备码 `DRRX-QTFT` 也明文。
- **担心**：小白可能怕"这是不是钓鱼链接/会不会泄露信息"；投屏演示也不好看。
- **证据**：`p2-08-dingtalk-login-started.png`。
- **建议**：加一句「这是钉钉官方登录链接，仅本次登录有效」；或默认折叠长 URL 只显示设备码 + "打开登录页"按钮。

### NEW-P3-2 登录弹窗「最多等 2 分钟」超时后的引导未验证

- **现象**：文案写「每 2 秒一次，最多等 2 分钟」，但超时后是否给"重新发起/改用终端命令"的明确提示，时间盒内未等到。
- **建议**：超时后把「重新发起登录」高亮为主按钮并提示可复制 `dws auth login --device` 在终端完成；补一条实测记录。

### NEW-P3-3 dws「未安装」分支未复现

- **现象**：本机已安装 dws v1.0.68-beta.1，弹窗直接进入"未登录"状态；未安装时的安装命令/引导（README 说是"未安装展示安装命令+复制"）本次未实测。
- **建议**：交付前用干净环境（或临时把 `DWS_BIN` 指向不存在路径）跑一遍，确认安装引导可读；本报告标注为未复现，不算通过。
